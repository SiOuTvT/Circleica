## 紫色主题 bug 修复（默认薄荷，DB 主题色加载即生效）
- 现象：默认主题色应为薄荷 `#5FA8A0`，但「初始化页面（Setup Wizard / 未初始化首页）一打开是紫色」。
- 根因：`ThemeScript`（layout 内联防闪烁内联脚本）原**只读 localStorage**（`site-theme-settings`/`site-theme-color`）套主题色，不读 DB。用户浏览器曾缓存过某次紫色，每页水合前套紫，盖过 DB/向导默认的薄荷。
- 修复（3 文件，tsc EXIT 0、eslint 0 error）：
  1. `src/components/theme-script.tsx`：`ThemeScript` 加 `themeColor` prop（`default "#5FA8A0"`）；脚本内注入 `var serverColor = ${JSON.stringify(themeColor)};`；取色顺序改 `serverColor || localColor || '#5FA8A0'`（删原 `if (!color) return;`）。**DB/服务端下发的主题色晋升为权威来源，覆盖陈旧 localStorage**。
  2. `src/app/layout.tsx`：import 加 `getSiteSetting`；`RootLayout` 在 `isSiteInitialized()` 后 `await getSiteSetting("themeColor", "#5FA8A0")` 取权威色；未初始化分支与已初始化分支两处 `<ThemeScript />` 均传 `themeColor={themeColor}`。
  3. `src/app/api/setup/route.ts`：初始化写入 `themeColor` 的兜底默认由棕色 `#E0A87C` 改为薄荷 `#5FA8A0`（向导 INITIAL 本就是薄荷，此处兜底一致）。
- 效果：未初始化页 / 已初始化页首屏均锁定薄荷；若用户在设置里主动改成紫色则 DB 存紫、serverColor 取紫（符合预期）；旧 localStorage 紫不再污染首屏。
- 旁证（已确认非紫源）：`globals.css:284` `--theme-color:#5FA8A0`（薄荷默认正确）、`theme-presets.ts` `THEME_PRESETS[0]` 薄荷、setup-wizard `INITIAL.themeColor` 薄荷、`theme-colors.ts applyThemeColor` 纯函数无紫色默认。紫源唯一在 ThemeScript 的 localStorage 只读逻辑。
